# Patton Story Mapping

Distilled from Jeff Patton's *User Story Mapping*: flat backlogs lose the
user's journey — arrange work as a map (backbone → walking skeleton →
releases) and ordering answers itself.

## Purpose

Turn a pile of stories into a shared picture of the product: what users do,
in what order, and which thin slice delivers value first.

## The method (workshop order)

1. **Frame first.** Who (personas, not "user"), what job they hire the
   product for, what done looks like in their words. No framing = map of
   features nobody takes a journey through.
2. **Backbone: the journey.** Major user activities left-to-right in
   journey order (the narrative spine). Keep it high-level (5-12 steps);
   detail comes later. Everyone must agree on the spine before any cards
   go below it.
3. **Walking skeleton.** Under each backbone step, the tasks; under tasks,
   the stories/subtasks. Then draw the first horizontal slice: the thinnest
   end-to-end journey a real user can complete (skeleton, not organs).
   THIS is the MVP candidate — everything above the line, nothing below.
4. **Release slices.** Second line = next release (thicker journey, happier
   path + key variants); subsequent lines = future. Slicing by journey
   (not by layer or component) keeps every release demonstrable and
   shippable.
5. **Maintain the map, not the list.** New stories land ON the map (journey
   position first, priority second). Groom by walking the journey; anything
   unmappable is either gold-plating or a missing journey step — decide
   which, out loud.

## Slicing discipline

- Each slice independently valuable AND releasable (demo-able to a user).
  "Backend first, UI later" slices are layer cakes, not journeys — rejected.
- Opportunities (learnings, experiments) marked on the map alongside
  stories — discovery and delivery share one picture.

## Verification

Map review: personas + framing stated, backbone agreed, skeleton slice
shippable end-to-end, each release slice demo-able, unmappable items
resolved. A backlog that cannot be walked is not a plan.
