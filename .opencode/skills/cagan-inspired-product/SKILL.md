# Cagan Inspired Product

Distilled from Marty Cagan's *Inspired* (with *Empowered* as the org
sequel): great products come from continuous discovery by empowered trios
(product, design, engineering) — not from stakeholders handing roadmaps to
feature factories.

## Purpose

De-risk WHAT to build across four dimensions (value, usability, feasibility,
viability) BEFORE committing engineering — with engineers in discovery, not
after it.

## The operating model

1. **Empowered trio, continuous discovery.** Product manager + designer +
   tech lead own problems, not tickets. Discovery runs weekly alongside
   delivery: interview, prototype, test, learn — a drumbeat, never a phase.
2. **Four-risk assessment per opportunity.** Value (will customers choose
   it?), Usability (can they figure it out?), Feasibility (can we build it
   with our skills/stack/time?), Viability (does it work for the business:
   cost, compliance, channels, sales?). Untested risk = scheduled surprise.
3. **Prototype fidelity ladder.** Start paper/figma (test value+usability in
   hours), escalate to coded spikes only for feasibility questions. Never
   build production quality to answer a discovery question — prototypes are
   disposable by design, and everyone must know it.
4. **Outcome roadmaps, not output roadmaps.** Commit to problems and
   measurable outcomes (activation, retention, task success), never to
   feature lists with dates. Features are hypotheses with success metrics
   attached; kill criteria written before launch.
5. **Engineers as inventors.** Feasibility input AND solution ideas come from
   engineering during discovery (technology enables product possibilities
   non-technical staff cannot see). A trio without a real engineer is a
   duo with a build queue.

## Org check (Empowered lens)

- Team topology: empowered product teams (own discovery+delivery) vs feature
  teams (take orders) — name which one each team is.
- Leadership: coaching and context, not roadmap assembly. Stakeholders bring
  problems; teams bring solutions.

## Verification

Opportunity packet per bet: the four risks each with evidence (not opinion),
prototype + test results, success metric + kill criterion, trio sign-off.
Engineering time without a packet is a feature factory shift.
