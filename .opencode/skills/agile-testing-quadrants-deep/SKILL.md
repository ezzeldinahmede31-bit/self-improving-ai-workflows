# Agile Testing Quadrants Deep

## Purpose

Balance all four agile testing quadrants per Brian Marick and Crispin: technology-facing team tests plus business-facing critique, each in its sprint place.

## When to use

Use when the user says 'testing quadrants', 'Q1 Q2 Q3 Q4', 'agile quadrant', 'Marick quadrants', 'whole-team testing'.

## Steps

1. Q1 technology-facing team: unit plus component, automated per commit.
2. Q2 business-facing team: functional plus examples, automated per story.
3. Q3 business-facing critique: exploratory plus usability per sprint.
4. Q4 technology-facing critique: performance plus security per release.
5. Review quadrant balance each retro from escape data.

## Anti-patterns

- Only Q2 automation with no Q1 foundation.
- Q3 exploration skipped under sprint pressure.
- Q4 crammed before release instead of incremental.
- Quadrants owned by silos instead of the whole team.

## Example

Sprint board columns tagged Q1/Q2/Q3 with Q4 checklist attached to release candidates.

## Verification

Each quadrant has owner plus cadence, balance reviewed per retro, escapes mapped to quadrants.
