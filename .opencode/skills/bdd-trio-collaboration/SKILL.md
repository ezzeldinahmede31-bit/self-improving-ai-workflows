# BDD Trio Collaboration

## Purpose

Build shared understanding before code: business, dev, and test refine stories together into concrete agreed examples.

## When to use

Use when the user says 'three amigos', 'trio session', 'shared understanding', 'ubiquitous language', 'BDD collaboration'.

## Steps

1. Convene the trio before sprint planning for unclear stories.
2. Walk rules first, then pin each rule with concrete examples.
3. Capture open questions with owners; block planning on answers.
4. Record the agreed language; reuse terms in code and tests.
5. Revisit examples at demo to confirm the built behavior.

## Anti-patterns

- Trio without the business voice present.
- Examples invented later by one role alone.
- Language drifting apart across code, tests, and docs.
- Sessions skipped for speed, paid back in rework.

## Example

Story refined into rule plus example cards, each example named and owned, questions tracked to answers.

## Verification

Trio cadenced, examples agreed pre-code, language reused, demo confirms.
