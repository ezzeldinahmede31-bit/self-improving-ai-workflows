# Weinberg Egoless Systems

Distilled from Gerald Weinberg (*Psychology of Computer Programming*,
*Becoming a Technical Leader*): software is a human system first — code
quality follows team congruence, and leadership is problem-solving made
visible, not authority exercised.

## Purpose

Fix the human system so the technical system can heal: egoless code,
congruent communication, and leadership anyone can practice.

## The core

1. **Egoless programming.** Code has bugs; programmers are not their code.
   Separate identity from artifact: critique code freely, receive critique
   without defense, rewrite without grief. Teams that personalize defects
   hide them; teams that externalize defects fix them. Code review is the
   ritual that proves which team you are.
2. **Congruence in communication.** Self + other + context, all honored:
   say what you observe (not your conclusion), own your part, stay on the
   problem. Blame patterns (placating, blaming, computing, distracting)
   diagnosed by name and redirected to the work.
3. **Problem-solving leadership.** Leadership = helping the team solve its
   problems:MOI model — Motivation (energy toward the goal), Organization
   (structure that fits), Ideas/innovation (room to think differently).
   Diagnose which leg limps before prescribing. Anyone can lead any leg at
   any time — title optional.
4. **The Orange-Juice-Test rule.** Vague requests ("get me juice") hide
   constraints (fresh? how much? by when?). Leaders restate the problem
   until the real requirements surface — most "technical failures" are
   unasked questions.
5. **Self-awareness as infrastructure.** Know your patterns under stress
   (your personal blame/avoidance style), name them to the team, invite
   correction. A leader who cannot be told they are wrong cannot learn what
   is right.

## Verification

Team retro answers: where did ego slow a fix this cycle? Which communication
was incongruent and what replaces it? Whose leadership (by name, any title)
moved each MOI leg? Unnamed dynamics are unmanaged dynamics.
