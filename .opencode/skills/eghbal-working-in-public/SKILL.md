# Eghbal Working in Public

Distilled from Nadia Eghbal's *Working in Public*: open source split into
two economies — federations (clubs, contributors co-own) and stadiums
(audiences watch a few maintainers perform). Most projects are stadiums;
govern them like stadiums or burn out the performers.

## Purpose

Keep an open project alive and healthy: funded attention, bounded maintainer
load, and a contributor path that actually converts.

## The playbook

1. **Know your shape.** Stadium (most-used projects: users >> contributors,
   maintainers are performers) vs federation (clubs with shared ownership).
   Stadium tactics: broadcast communication, maintainer leverage, ruthless
   scope control. Federation tactics: distributed ownership, consensus
   process. Mismatched governance (stadium project run as federation)
   stalls everything.
2. **Maintainer leverage first.** Templates, bots, CI, and clear
   contribution docs multiply the scarcest resource: maintainer attention.
   Every repeated question becomes documentation; every repeated task
   becomes automation. Saying no to scope is the job — growth without
   leverage is just more unpaid work.
3. **Design the contributor funnel.** Reader -> user -> reporter ->
   contributor -> maintainer, with explicit on-ramps at each step (good
   first issues that are REAL, mentored PRs, public thanks). Measure
   conversion, not stars — stars are applause, contributors are payroll.
4. **Fund the work honestly.** Options mapped: corporate sponsorship (align
   incentives in writing), foundations/grants, dual-license or open-core
   (commercial rights sold, code stays open), support contracts, donations
   (supplementary, rarely sufficient). Pick the model whose incentives match
   the project's shape; revisit yearly.
5. **Govern before crisis.** Decision rights written down (BDFL? committee?
   consensus?), security response path (private reporting, embargo policy),
   code of conduct enforced (with named enforcers), succession plan (bus
   factor > 1 for every critical role, including yours).

## Maintainer health (non-optional)

- Boundaries published (response times, scope, office hours); guilt is not
  a governance model. Sabbaticals and co-maintainers are infrastructure.
- Toxicity handled fast and visibly — one abusive participant costs more
  contributors than any feature gains.

## Verification

Project health review: shape named, leverage inventory current, funnel
metrics tracked, funding model stated, governance + succession docs exist,
maintainer load sustainable on paper. Missing pieces are risks with owners.
