# QA Coaching Patterns

## Purpose

Multiply quality through people: coach developers in testing craft, grow guilds, advocate risk thinking, never gatekeep quality.

## When to use

Use when the user says 'QA coaching', 'whole-team quality', 'testing guild', 'quality advocacy', 'coach developers', 'quality culture'.

## Steps

1. Pair with developers on test design, not just defect reports.
2. Run guild sessions on one technique at a time with live examples.
3. Coach risk thinking into planning and reviews.
4. Celebrate prevented defects as loudly as found ones.
5. Grow testing skills across roles; track capability growth.

## Anti-patterns

- QA as the quality gatekeeper while devs throw code over walls.
- Coaching as lecturing without pairing.
- Guilds that meet without practicing.
- Advocacy without data from escapes and flow metrics.

## Example

Guild session: thirty minutes pairing on property-based tests for one real story.

## Verification

Pairing cadenced, guilds practicing, risk language in planning, capability growth visible.
