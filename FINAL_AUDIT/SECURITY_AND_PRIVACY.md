# SECURITY_AND_PRIVACY.md — مراجعة التهديدات والضوابط (2026-10-11)

## نموذج التهديد (على الملفات الحقيقية)
| التهديد | الحالة قبل | الضابط الآن | المتبقي |
|---|---|---|---|
| تزوير webhook / إعادة الإرسال | لا حماية في sub-flows | idempotency keys + staff secret header (موجود) + TTLs | sub-flow webhooks داخلية بلا توقيع — مقبولة (غير معرضة خارجيًا) |
| سرقة الأسرار | 0 أسرار في الملفات ✅ (مفحوص آليًا) | credentials بالمراجع فقط + `$env` | مراجعة صلاحيات البوتات دوريًا (تشغيلي) |
| بوت Telegram خارج القائمة | تحقق سر fail-closed موجود ✅ | أُبقي عليه + اختبار منطق | — |
| مريض يعدّل حجز غيره | **ممكن بـ eventId** | بوابة ملكية + سجل رفض (منفذ ومختبر) | مراجعة سجل الرفض أسبوعيًا (تشغيلي) |
| prompt injection | بلا قاعدة | قاعدة صريحة + فصل الأدوات + اختبار ملكية | اختبار حي شامل محجوب (يحتاج جلسة) |
| SSRF عبر URLs | لا يوجد جلب URLs من مدخلات (العقد تستدعي Google/Data-tables ثابتة) | لا تغيير مطلوب | إعادة الفحص عند أي عقدة URL ديناميكية |
| تجاوز المعدل | retry+timeout موجودة؛ حدود عددية لا | Backlog: حد يومي لكل محادثة (مقترح) |
| تسريب PII في logs | أسماء مرضى في وصف حدث التقويم (ضرورة تشغيلية) | توثيق + عدم وضع PII في مفاتيح/رسائل تشخيص؛ سجلات الرفض chatId فقط | مراجعة احتفاظ التقويم |
| حذف بلا أثر | كان ممكنًا | سجلات audit:deny / audit:saga + إحصاءات | لوحة عرض السجلات (Backlog) |
| إدارة منتهكة | سر + أوامر staff-only ✅ | أُبقي + اختبار | — |
| نسخ احتياطي بأسرار | tgz يحتوي قاعدة n8n (بها credentials مشفرة) | محفوظ محليًا فقط + تحذير عدم رفعه | تشفير النسخة بكلمة سر (مقترح) |

## قانون حماية البيانات المصري (من مصادر رسمية، 2026-10-11)
- القانون 151/2020 + اللائحة 816/2025 (pdpc.gov.eg): موافقة صريحة قبل المعالجة، حقوق 9 للأفراد، مسؤول حماية بيانات، ترخيص لنقل البيانات خارج مصر (سحابات أجنبية!)، ضوابط صارمة للتسويق الإلكتروني، موافقة كتابية للبيانات الحساسة (الصحية!) والقاصرين، عقوبات تصل للحبس + 500K-5M جنيه.
- **ما ينطبق علينا**: بيانات المرضى (أسماء/هواتف/مواعيد = شخصية؛ التشخيصات = حساسة → **لا نجمعها أصلًا** وهذا قرار تصميمي صحيح)، موافقة صريحة مطلوبة قبل التذكيرات التسويقية (التشغيلية للموعد المحجوز: مبرر تعاقدي)، نقل البيانات لخوادم خارج مصر (Google/OpenAI/NVIDIA) يحتاج ترتيبًا تعاقديًا وترخيصًا — **يحتاج مراجعة قانونية متخصصة قبل أي إنتاج**.
- **لا أصدر شهادة امتثال.** المطلوب قبل الإنتاج: صياغة موافقة عربية + سياسة احتفاظ/حذف + تعيين مسؤول + مراجعة محامٍ.

## الخصوصية المنفذة
- أقل بيانات: chat/phone/اسم/موعد فقط. لا تشخيص ولا صور ولا تأمين في السجلات الجديدة.
- سجلات الرفض/التعويض: chatId + eventId فقط.
- التقارير: تجميعات بلا أسماء (الأجندة تعرض الوقت والطبيب فقط).
